# 事件驱动型智能体

## 核心理念

**事件驱动**（Event-Driven）通常指事件驱动架构（Event-Driven Architecture, EDA）或事件驱动编程，是==一种以“事件”为核心来构建软件或业务逻辑的设计模型==。

    典型的事件驱动架构是IEC61499 基于事件的功能块网络。它是一种基于事件的异步控制方式。相比之下，IEC61131 是周期扫描的同步控制方式。

在这里，我们不在展开讨论基于事件的架构以及IEC61499 功能块网络。而重点研究基于事件的Agent 架构。

事件驱动的Agent架构与传统的事件驱动架构有什么区别呢？传统事件驱动架构是基于规则的操作。事件的发生和处理的操作是完全确定的。例如通过一个有限状态机就能确定下一个状态和操作。在事件驱动的Agent架构中，操作的选择是由LLM 推理确定的，他可能遵循的规则，也可能完全由LLM推理决定。

      事件驱动的Agent架构简化了事件驱动系统。拿IEC61499 功能块网络做比较，在事件驱动Agent 中，只要以系统进程的方式编写功能块中的算法就可以了，事件-操作的状态机由LLM 推理完成。

一个基本的事实也非常重要，如果事件与操作之间存在传统的规则，LLM 目前的推理能力完全能够按照规则选择确定的操作。只要操作之间的上下文描述误差距离足够的大，LLM 已经具备了判决能力。

如果系统十分复杂，规则非常多，可以使用RAG 系统进行检索。

AI Code 的能力已经很强，已经完全没有必要使用各种基本的逻辑运算，数学运算和过程控制的程序模块（功能块），需要的是一个大的功能块。他们以线程形式运行。这样大幅度简化的代码设计，大多数面向专业领域的语言和低代码系统在AI Code 面前显得多余。

### AI 代理层

- **运行时**

   收到事件消息时，处理事件消息。根据事件的那些调用基于规则的处理程序或者调用LLM 处理。异步处理事件将新建一个任务进程来实现。

- **任务进程**

有些操作需要复杂的异步循环操作。例如：

- 循环读取modbus 总线的数据，按照PID 算法控制温度。

- 当货物车到达时，控制机械臂拿起物品放到工作台上。

这些异步操作由任务进程完成。任务进程是用户态进程。任务进程一个大功能块。

AI 代理层与应用相关，可以由Claude Code，Codex 等AI Code 工具生成。出于安全的考虑，应该使用Wasm 运行时这样的沙盒容器中运行。

- **环境**

环境是系统的全局变量，包括了状态，公共变量。历史数据。如果数据量很大，可以使用数据库和外部存储设备。

### Agent 的API

Agent API 是一个标准的程序库，包括两个部分：

- WasmAPI

WASM 容器中的App 通过调用API 程序库访问系统

- 系统API

系统进程调用的API程序库

### 消息队列

每个进程都有一个消息队列，接受发给该进程的消息。消息可分为

- 事件

- 操作

 消息的格式符合 JSON-RPC 2.0

## 工作流程

系统以事件驱动系统的形式运行，硬件进程持续地处理硬件的IO，采集属性参数，必要时生成结构化事件，通知AI 代理的运行时处理事件。事件处理的方法有两种：

- 基于规则的行为

-  LLM 驱动的自主推理

事件处理的结果会选择操作（Action），通过Action 消息发送给系统进程。同时也会改变环境变量。基于规则的行为到 LLM 驱动的自主推理。环境变量作为LLM 推理过程中的上下文。

 Agent 的交互后端也是系统进程，他们产生统一的结构化事件。其中请求是事件，相应是操作（action）

### 最小系统

      一个硬件进程，模拟温度传感器。定时更新温度的值。温度范围-10度到+80度，当温度低于0度，或者高于60度。产生告警事件。该物理进程有如下几个操作：

- 启动加热

- 停止加热

- 读取温度值

 系统进程包含一个简单的web server和websocket 后端。前端使用典型的大语言模型对话界面。告警信息在对话框中显示。
